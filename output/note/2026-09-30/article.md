# 手描きスケッチ→生成AI→3D→CAD｜プロダクトデザイナーの実務フロー7ステップと失敗集

生成AIで製品レンダーが一瞬で出るようになりました。でも、実務で本当に困るのはその先です。「AIが作った3Dデータ、CADで使えないんだけど？」「未発表製品のスケッチ、外部のAIに入れて大丈夫？」。この記事では、プロダクトデザイナーの僕が、手描きスケッチから生成AI・Blender・CADをつないで量産検討モデルまで持っていく7ステップを、工程表・機密の線引き表・失敗集つきで公開します。

## 2. 最初に決める：社外AIに入れていい情報 / ダメな情報

工程に入る前に、これだけは無料で書いておきます。**企業デザイナーが一番やってはいけないのは、未発表製品の情報を、会社が認めていないAIサービスに入れること** です。

| 情報 | 社外AIに入れてよいか | 理由・代替 |
|------|:--------------------:|------------|
| 公開済み製品の写真 | △ 社内ルール次第 | 自社の権利物。ルールを確認 |
| 未発表製品のスケッチ・図面 | × 原則NG | 会社が契約・許可したツール（学習に使われない設定）のみ |

| 個人の練習作品・副業の自主制作 | ○ | 規約とライセンスは確認 |

各AIサービスが「入力データを学習に使うか」は、プランや設定で変わります。**最新の利用規約と、会社の規程の両方** を確認してください。

## 3. 工程別：やり方と判断基準

所要時間は小型製品1点・初回提案までの **目安** です。自分で1回計測して置き換えてください。

### 工程1：要件メモ（目安 15分）

AIに何かを入れる前に、紙に3行だけ書きます。

```
・変えられない寸法：例）内部基板 60×40×12mm、電池 単3×2
・必須の部品：例）電源ボタン1、USB-C 1、LED 1
・使用シーン：例）キッチンの壁に貼る。濡れた手で押す
```

**判断基準**: この3行が無いままAIに入れると、見た目だけ良くて入らない案が量産されます（失敗集①）。

### 工程2：手描きサムネイル（目安 30〜45分）

- 1案あたり 1〜2分、**名刺サイズ** で 20〜30枚
- 描くのは「形の構成」だけ。陰影・質感は描かない（それはAIの仕事）
- 1枚ごとに「この案の一言コンセプト」をメモする

**判断基準**: ここを飛ばしてAIにテキストだけで案出しさせると、どこかで見た形が並びます。**アイデアの起点は必ず手描きにする。** AIは起点ではなく増幅器です。

### 工程3：AIでレンダー展開（目安 1〜2時間）

- サムネイルから **8〜10枚** を選んでAIに入れる
- 1枚ごとに振るのは **「色・素材（CMF）」「角度」「使用シーン」の3軸だけ**
- 形そのものを大きく変えさせない（形が変わったら、それは新しいスケッチとして描き直す）

プロンプトより、**入力スケッチの線の質** が結果を左右します。輪郭線をはっきり、パーティングライン（部品の分割線）も線で描いておくと、分割の位置が保たれやすくなります。

### 工程4：評価・選定（目安 30分）

レンダーの見た目に引っ張られないよう、**評価表で機械的に絞ります**。

| 評価軸 | 重み | A案 | B案 | C案 |
|--------|:----:|:---:|:---:|:---:|
| 要件メモの寸法に入るか | ×3 | | | |
| 部品構成が成立しそうか（分割・抜き勾配） | ×3 | | | |
| 使用シーンで使いやすいか | ×2 | | | |
| ブランドらしさ | ×2 | | | |
| 新しさ | ×1 | | | |

各項目 1〜3点 × 重み。**上位3案＋「落とした理由」を1行ずつ** 残します。落とした理由は、上司やクライアントに「他の案は？」と聞かれたときの答えになります。

### 工程5：AIで3Dボリューム確認（目安 30分）

Vizcom などの 2D→3D 生成で、**ボリューム感の確認用** メッシュを作ります。Vizcom の Multiview 3D は、2〜5枚の視点違いのスケッチから生成できます（2026年9月時点）。

- 正面・側面・斜めの3視点を描いて入れると、厚みの破綻が減る
- 見るのは **「厚み・重心・持ったときの大きさ感」だけ**
- 細部の形状はここでは見ない（AIのメッシュは細部が不正確）

**判断基準**: この段階で「思ったより厚い／薄い」が分かれば、工程5の目的は達成です。

### 工程6：CADで引き直す（目安 3〜6時間）★一番大事

ここがこの記事の核心です。

**AIが作った3Dメッシュは、CADのソリッドに「変換」しません。下敷きにして「引き直し」ます。**

理由は3つ。

1. **寸法が無い**: AIメッシュは縮尺も単位も任意。寸法は要件メモから入れ直すしかない
2. **面が汚い**: 三角ポリゴンの集まりなので、変換しても曲面がガタガタで、フィレットや抜き勾配が付けられない
3. **設計意図が無い**: どこが基準面で、どこが部品の分割か、データに情報が無い。後の設計変更に耐えない

**手順（Blender → Fusion の例）**

1. Blender でメッシュを読み込み、`N` パネル → Item → **Dimensions** で、要件メモの外形寸法に合わせる
2. 不要な細部を落とす：Decimate モディファイアで軽くする（目的は下敷きなので粗くて良い）
3. **単位を確認**して OBJ / STL で書き出す（Blender の既定はメートル。CAD 側がミリ前提だと 1000倍・1/1000 になる → 失敗集②）
4. Fusion で `挿入 → メッシュを挿入` し、読み込み時の単位を合わせる
5. 原点・向きを合わせ、メッシュを **半透明の下敷き** にする
6. 正面・側面・上面の3平面にスケッチを作り、メッシュの輪郭を **なぞらずに**、要件メモの寸法を優先して線を引く
7. 押し出し・ロフトで大まかなボディを作り、分割線・抜き勾配・フィレットを設計意図どおりに入れる
8. 最後にメッシュを非表示にして、ソリッドだけで形が成立しているか確認する

**判断基準**: メッシュと形がズレてもいい。**寸法と部品構成が優先**です。AIの形はあくまで「このくらいのボリューム」という参考情報です。

### 工程7：レンダー・プレゼン（目安 1〜2時間）

- CADのソリッドを KeyShot / Blender に持っていき、**工程3のAIレンダーと同じ色・素材・角度** で再現する
- 提案資料には「AIレンダー（初期案）」と「CADからのレンダー（検討モデル）」を並べ、**何が変わったか（厚み・分割・寸法）を注記** する

AIレンダーのほうが見栄えが良いことはよくあります。でも、並べて差分を説明できることが、「このデザイナーは作れる形を提案している」という信頼になります。

## 4. 失敗集

### 失敗① 要件メモなしでAIに投げて、全案が基板に入らなかった
- **何が起きた**: 【要記入: 実体験。例「かっこいい薄型案を10案出したが、電池が入る厚みの案が1つも無かった。2日分がやり直し」】
- **原因**: 変えられない寸法をAIにも自分にも与えていなかった
- **対策**: 工程1の3行メモを先に書く。サムネイルの横に内部部品の外形を薄く描いておく

### 失敗② メッシュの単位がズレて、CADで1000倍の大きさになった
- **何が起きた**: Blender（メートル）から書き出したメッシュを、ミリ前提で読み込んで巨大化／極小化する。よくある事故です
- **原因**: 書き出し側と読み込み側の単位を確認していない
- **対策**: 書き出す前に外形寸法を数値で確認し、読み込み時に単位を明示的に選ぶ。読み込み後、**外形寸法を1回計測** してから作業を始める

### 失敗③ AIメッシュをそのままCADに変換して、後で作り直しになった
- **何が起きた**: 【要記入: 実体験、または見聞きした例。例「変換したボディにフィレットが掛からず、結局ゼロから引き直した。半日ロス」】
- **原因**: メッシュには寸法も設計意図も無い
- **対策**: 工程6の「変換しない、引き直す」を徹底する

### 失敗④ AIレンダーで決まった案が、試作で「思っていたのと違う」と言われた
- **何が起きた**: AIの陰影・反射で実物より高級に見えていた
- **原因**: AIレンダーとCADレンダーの差を説明していなかった
- **対策**: 工程7で「初期案」と「検討モデル」を並べ、差分を注記する
